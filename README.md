# Motorlog · Vehicle Workspace

Motorlog is a PHP 8.2+ website for Apache/XAMPP and a synchronized Python 3.10+ Windows desktop GUI. The two clients use one authenticated PHP API and one SQLite or MySQL/MariaDB database. The desktop app has no independent fleet database. Version: see [`VERSION`](VERSION).

## 1. Install on Windows XAMPP

1. Extract the release. Copy the **`motorlog` folder itself** into `C:\xampp\htdocs\` so `C:\xampp\htdocs\motorlog\index.php` exists. In Explorer/PowerShell verify that `.htaccess` was copied. No Node, Composer, Docker, or internet connection is needed to install the PHP site or its catalog.
2. In XAMPP Control Panel open Apache → Config → `php.ini`. Confirm `extension=pdo_sqlite` for SQLite or `extension=pdo_mysql` for MySQL/MariaDB, and `extension=fileinfo`, `extension=gd`, `extension=mbstring`. GD enables full image decoding and embeds evidence images in downloadable PDFs. Make sure `post_max_size` is at least `8M` and `memory_limit` is at least `128M`. Confirm Apache has `mod_authz_core` and `mod_setenvif`, with `AllowOverride All` for the Motorlog folder; the default XAMPP htdocs configuration normally allows this. Restart Apache after changes. For hosted use, disable PHP error display and use HTTPS for the site and API. Keep XAMPP admin tools restricted to localhost.
3. **Private storage**: by default, with document root `C:\xampp\htdocs`, the installer creates `C:\xampp\motorlog-private\motorlog`. Before going live, restrict that directory with Windows Security/NTFS permissions: allow Modify only to the account running Apache and the account that administers/backups the app; remove general read access on inherited permissions as appropriate. Do not put it under htdocs or expose it via `Alias`. If your Apache account cannot create the default directory, precreate a suitable private folder and set `MOTORLOG_DATA_DIR` to its **absolute** path in the service environment or the Apache virtual host using `SetEnv MOTORLOG_DATA_DIR "D:/Private/Motorlog"` (`mod_env` and Apache restart required). Set the same environment for CLI commands. For nonstandard CLI layouts also set `MOTORLOG_DOCUMENT_ROOT` to the actual public root. Per-install private storage paths must differ. Protect backups with the same ACLs. The application refuses a private path inside its public root.
4. **SQLite** (recommended): start Apache. No other service or empty database to create. SQLite will be initialized and published in the private folder; no database comes with this release.
5. **MySQL/MariaDB**: start both Apache and MySQL in XAMPP. In localhost-only phpMyAdmin create an **empty, dedicated `utf8mb4` database**, e.g. `motorlog`, plus a dedicated user with standard schema (CREATE/ALTER/REFERENCES) and CRUD privileges on that database only. Grant access for the actual connecting host (`127.0.0.1` by default). Do not reuse a database containing existing tables or use server root in deployment. Select MySQL/MariaDB on the setup screen and enter host, port (normally 3306), database, user, and password. No cloud service is necessary.
6. Open `http://localhost/motorlog/` (include the final slash). Select the database and **Test connection**, set site name, currency/units and administrator details, and add the first vehicle. To recreate the competition mileage example, enter `120000` for the baseline and installation vehicle odometers and `25000` for engine mileage. Use **Install workspace**. The user is signed in on success. Verify that `config.php` and `config.lock` are in the private folder, not htdocs. `http://localhost/motorlog/?r=install` should deny both GET and POST with HTTP 423 even after restarting Apache.

The wizard is serialized with a filesystem guard and, for MySQL, an advisory database lock. On SQLite an unpublished staged database is discarded after a failed attempt. On MySQL additive DDL may be left by an interrupted attempt because the engine commits DDL; the account/site/vehicle transaction is all-or-nothing. Retry with the same dedicated database and identity to resume when none of those rows were committed. Never copy the example config onto a new installation to skip setup. To use a fresh, separate site for testing, use a new directory/storage and a new empty database, not a previous workspace.

## 2. Start the Windows desktop GUI

1. Install [Python for Windows](https://www.python.org/downloads/windows/), version 3.10 or later, with the `py` launcher and **Tcl/Tk and IDLE** selected. Go to Settings in the running website, choose **Generate API token** and copy it immediately. Tokens are stored hashed on the server, expire automatically and can be revoked; treat them as passwords.
2. Use **Download Python app / script** for the maintained single-file `motorlog.py`, or **Download Windows bundle** for the script, requirements, and authoritative version file. Extract the bundle into a normal folder like `C:\Users\you\Downloads\MotorlogDesktop`.
3. From a PowerShell window in that folder, run:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe .\motorlog.py
   ```

   If you downloaded **only the `.py`**, run `py -m pip install Pillow` (optional for better JPEG/PNG previews) and `py .\motorlog.py`. If offline, `py .\motorlog.py` still works without Pillow; native Tk displays PNG previews, and both image types can be uploaded. To run without a console after verifying the installation, use `pyw .\motorlog.py`. Do not launch by pasting code into a shell.
4. Enter your **exact website URL** and the token; **Test and connect** checks server availability/onboarding and then authentication. HTTP is appropriate for `localhost` during setup; use HTTPS for remote access. Connection settings and light/dark theme are editable and persistent. Remembering a token on Windows uses current-user DPAPI. Local preferences are stored in `%LOCALAPPDATA%\Motorlog`; no record data is stored there. Requests run in a background pool; GUI updates stay on the main thread. Use Refresh/F5 to see changes from the website.

For desktop printing, choose Print preview to open the authenticated PDF in the installed Windows PDF viewer, then print from the viewer. The temporary PDFs are removed on normal app exit when the viewer allows it; close the viewer, and clean `%TEMP%\motorlog-print-*` after interruption if needed. Explicitly exported PDFs/CSVs are sensitive files at the destination you choose. The browser offers a clean print view and can also export the server PDF.

## 3. Recording and workflow notes

- **Vehicles:** use the type, make and model pickers, or Other to enter a custom name (also available for makes without models). Existing manual names aren't forced into the catalog. Vehicle identification and independent engine baselines are stored separately. Retired engines freeze at the replacement reading. The highest validated vehicle reading is retained after edits/deletions. Dated observations require a monotonic timeline; overlapping same-day trip ranges and contradictory timed inspections are rejected. Untimed same-day fuel readings are ordered by odometer, not by the sequence they were entered. Migration preserves historical values rather than silently repairing unknown records.
- **Fuel:** use Gallons (US) and the unit price, then explicitly mark full-tank fills. First full fill is a baseline. Known partial fills count toward the next full interval; legacy rows without details interrupt the interval. Kilometers are converted to miles for US MPG. Fuel amounts use fixed-point arithmetic and are rounded to the configured currency; the server never uses a client-supplied fuel total.
- **Mechanics:** make a mechanic profile, then an invoice. Each invoice owns one linked repair expense. A payment is a debt movement only and cannot overpay. Edit linked expenses in Mechanics rather than deleting them in the general expense list.
- **Drivers/inspections:** use private driver profiles and dated records. Deactivation does not delete attribution. New inspection rows are blank; choose every result, add explanatory notes for findings, and explicitly acknowledge before submitting. Drafts autosave to the server; input stays open after errors. A concurrent draft edit receives a revision conflict instead of overwriting the other device. Copy any unsaved edits before reopening the current revision. A completed sheet does not certify safety. Follow-up status is independent of the original result. Week dates are Mondays; next due is the following Monday. Server completion timestamps and workspace calendar calculations use UTC. Correct submitted sheets via a new revision, not by overwriting the original.
- **Bills of sale:** the general template does not replace official title transfer or automatically meet legal requirements. Set jurisdiction-specific templates under Settings with editable suggested terms and witness/notary fields. Vehicle prefills are editable snapshots. All price/party/disclosure fields can be filled in a draft; required details and explicit review are enforced at finalization. Print for handwritten signatures. Signed status is an explicit record of confirmed offline signing; Motorlog does not produce, insert, or certify electronic signatures. Corrections preserve finalized and signed originals. Exports contain personal details and should be managed privately.
- Protected photos accept JPEG/PNG up to 5 MB. Gallery and inspection evidence are separately owned. Reports and image endpoints require an authorized session or API token; PDFs are generated on demand, not published to a public directory. CSV is filtered and includes drivers and financial amounts. Motorlog does not claim legal or commercial-fleet compliance.

## 4. Offline catalog and refresh

The release includes a complete, type-filtered **NHTSA vPIC** snapshot of **1,891 makes** and **11,658 distinct make/model pairs**, retrieved **2026-11-20 UTC**, including 195 passenger-car makes and 1,703 motorcycle makes (seven in both). See [provenance and method](catalog/PROVENANCE.md). This is not a claim to list every vehicle ever produced. The November 18 figures in the contest prompt refer to a different snapshot.

Optional online refresh, from the application directory:

```powershell
py .\tools\refresh_catalog.py
```

Optional offline import: obtain the four official responses documented in `catalog/PROVENANCE.md`, save them as `car.json`, `motorcycle.json`, `car.csv`, `motorcycle.csv` in a local folder, then run `py .\tools\refresh_catalog.py --input-dir C:\CatalogResponses`. Use responses from the same retrieval. The command validates vehicle types, relationships, counts and minimum volumes, and replaces only the catalog file after success. Keep a copy of the old catalog if comparing versions. An upstream error does not change the bundled catalog or vehicle profiles.

## 5. Backup, upgrade, and lock recovery

- **Back up first.** Stop Apache. Copy the complete private directory (configuration, lock, SQLite file including any journal sidecars, photos; session files can be excluded if desired) to protected storage. For MySQL additionally export the entire dedicated database in phpMyAdmin or with the matching `mariadb-dump`/`mysqldump`. Never use a public web folder for backups. Keep a known-good source copy too. Test restoration in a separate private folder and database.
- **Updates:** set a **public** GitHub owner/repository under Settings; by default there is no repository configured. Stable published GitHub releases use semantic versions. The server caches requests (one hour normally, manual checks no more often than once per minute). A newer stable version offers release notes, Download, and Later. Download opens the application ZIP if provided, otherwise the tagged source ZIP. Later remembers the release; a manual check can show it again. No app code is downloaded or executed automatically. A missing repo/release or network failure does not affect regular features. Private GitHub repositories/tokens are not supported.
- **Manual upgrade:** verify the release, stop Apache, make the backups above, and replace only the source files in `htdocs\motorlog`. Leave your private storage, database, config, lock and photos untouched. Then from the source folder (or adjust the XAMPP path):

  ```powershell
  & C:\xampp\php\php.exe .\tools\console.php status
  & C:\xampp\php\php.exe .\tools\console.php migrate --backed-up
  ```

  Migrations are versioned and additive, cover Motorlog schema versions 1 through 3, and do not drop old trips, expenses, or driver assignments. Version 2 adds nullable driver and fuel-detail columns; legacy records remain unassigned/incomplete. Version 3 adds document and evidence records and restores the high-water mileage from legacy trip readings. Migrations can be re-run after interruption. Start Apache and refresh both clients; replace the desktop script/companion `VERSION` manually after downloading a verified update. If a new version requires rollback, restore both the old source and its corresponding backup privately. Do not point old code at a newer schema.
- **Lost `config.lock`:** the installer blocks if it sees a config, SQLite file, or an existing initialized MySQL schema. Stop Apache, back up current files and data, restore the original `config.php` or a verified private backup if missing, and run `& C:\xampp\php\php.exe .\tools\console.php recover-lock --backed-up`. It validates the committed workspace and recreates a credential-free lock without reseeding or altering rows. It can use a staged `setup.pending.php` from an interrupted commit if the workspace really exists. If you no longer have a valid config or pending file but still have the correct existing DB credentials, use `tools/config.example.php` **as a reference** to recreate the config in the private folder and then recover. If a lock still exists but config is missing, restore config; do not delete the lock. If a setup attempt left only an uncommitted empty MySQL schema and you must abandon it, back up the pending file and the schema, use a new dedicated schema, and move the abandoned pending file out of the private directory only after verifying it has no installed settings/administrator. Never reset an existing workspace via Setup.

## 6. API and testing

All endpoints are relative to the website root (`/motorlog/`) with `?r=...`. `ping` is public and reports whether onboarding is complete; `download` provides the `.py`; `state`, `catalog` (except fresh setup), `document`, `image`, `pdf`, `print`, `trip-csv`, `expense-csv`, and `updates` require authorization. Desktop calls send `Authorization: Bearer <token>`. Browser writes use an authenticated cookie with a CSRF header. `POST ?r=save` uses JSON with `entity`, `action` and `data` as in `desktop/motorlog.py`, plus a unique `Idempotency-Key`. Sending identical bytes with the same key returns the original result; reusing a key for a different payload is rejected. Keep the exact payload and key for a retry. Tokens are only managed via the authenticated browser. Dataset and migration source are `catalog/vpic.json` and `lib/schema.php`.

Run tests from the application directory, e.g. `& C:\xampp\php\php.exe .\tests\domain.php` and set `$env:MOTORLOG_TEST_PHP = 'C:\xampp\php\php.exe'` before `py .\tests\integration.py`. Tests use temporary SQLite storage and exercise the actual PHP API and desktop HTTP transport. For MySQL, **use an empty disposable dedicated test schema** and set `MOTORLOG_TEST_MYSQL_DATABASE`, `MOTORLOG_TEST_MYSQL_HOST`, `MOTORLOG_TEST_MYSQL_PORT`, `MOTORLOG_TEST_MYSQL_USER` and `MOTORLOG_TEST_MYSQL_PASSWORD`. The optional integration test initializes it and leaves the test records; drop it yourself only after confirming it is the disposable test schema. For an end-to-end UI smoke test, make a temporary workspace, follow the onboarding steps in a normal browser, create a desktop token, connect with both an invalid and a valid token, then alternate recording a trip/draft/payment in the two interfaces and use Refresh. To test release prompts, use a public test repository you control with published stable, invalid, and prerelease tags; respect the cache and never use a private repo credential.

Optional local UI checks: `node tests/browser-smoke.mjs` (Node 22+, Chromium available as `chromium` or `CHROMIUM`) and `py tests\desktop_smoke.py` (Tcl/Tk with a display). These create disposable fixtures and do not need an online release repo. Package both downloads with `py tools\package_release.py --source-zip C:\Releases\motorlog-xampp.zip`.
